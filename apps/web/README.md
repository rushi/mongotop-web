# MongoTop Frontend

React dashboard for the MongoTop API. Streams `db.currentOp()`, connected clients, and collection activity over Server-Sent Events.

Setup, configuration, and Docker instructions live in the [root README](../../README.md). This file covers only what is specific to `apps/web`.

## Running

Run the dashboard from the repo root so the API starts alongside it and the generated config stays current:

```bash
pnpm run dev
```

The dashboard starts on http://localhost:7000 and expects the API on http://localhost:7001.

To run the production build locally:

```bash
pnpm run build
pnpm run start:web
```

That serves the built assets with `vite preview` on http://localhost:7010.

## Configuration

There are no `.env` files and no `import.meta.env` reads. `scripts/generate-web-config.js` writes the gitignored `src/config.ts` from the YAML in `config/`, and it runs automatically before `dev` and `build`. Import the generated values with `import config from "../config"`.

## Tech Stack

| Concern   | Choice                                      |
| --------- | ------------------------------------------- |
| Routing   | TanStack Router (file-based, `src/routes/`) |
| Rendering | React 19 + Vite                             |
| State     | Zustand with `persist` to localStorage      |
| URL state | nuqs                                        |
| Tables    | TanStack Virtual                            |
| UI        | shadcn/ui (Radix UI + Tailwind CSS v4)      |
| Transport | EventSource (SSE) and Axios                 |

## Routes

| Path        | File                      | Shows                                                                        |
| ----------- | ------------------------- | ---------------------------------------------------------------------------- |
| `/`         | `src/routes/index.tsx`    | Query monitor: live `currentOp()` table, summary stats, query details        |
| `/clients`  | `src/routes/clients.tsx`  | Connected clients grouped by client and user, filterable by replica set node |
| `/activity` | `src/routes/activity.tsx` | Collection activity from the `top` command, per-interval or cumulative       |

`src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin. Do not edit it by hand.

```
│   ├── connected-clients/     # Client table and summary

│   └── ui/                    # shadcn/ui primitives

├── lib/                       # Formatters (formatActivity, isInternalIp) and the cn() helper
├── routes/                    # File-based routes
├── store/                     # Zustand stores
└── utils/                     # api.ts (Axios client), queryIssueDetector.ts
```

## State

Two persisted Zustand stores:

- `store/preferences.ts` (`mongo-query-top-preferences`): selected server, pause state, IP filter, per-server read preference.
- `store/settings.ts` (`mongo-query-top-settings`): default filters, auto-save rules, query issue thresholds, UI preferences.

The localStorage keys predate the `mongotop-web` rename and intentionally keep the old name. Changing either key discards every existing user's saved state, since neither store defines a `migrate`.

Filter state that belongs in a shareable link (server, read preference, activity view mode) lives in the URL through nuqs, not in these stores.

## API Client

`src/utils/api.ts` holds the Axios instance, the `X-API-Key` header, and the response interceptor that converts API errors into structured evlog errors. Add new calls there rather than importing Axios elsewhere.

## Tests

```bash
pnpm test
```

Vitest, run from `apps/web`. Covers the pure formatters in `src/lib/`.
